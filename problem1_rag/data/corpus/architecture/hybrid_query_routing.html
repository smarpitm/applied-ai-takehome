Hybrid Query Routing and Metadata Filters

Pre-Filtering vs Post-Filtering

NimbusStack pushes metadata predicates such as file_type and source_id directly into the LanceDB columnar scan before scoring vectors. Pushing selective filters down avoids wasted distance computations and prevents top-k starvation when a filter matches fewer than 5% of rows. Post-filtering after global top-k ANN search frequently returns fewer than k chunks or zero matching documents when the requested topic represents a small fraction of the overall index.

No-Context Similarity Gate

Before invoking the downstream generation model, the router verifies that at least one retrieved chunk meets the calibrated cosine similarity threshold of 0.665 for BAAI/bge-small-en-v1.5. Queries scoring below threshold terminate early with a structured no-context refusal and incur zero generation tokens. This gate eliminates unsupported hallucinations on out-of-domain questions while cutting wasted LLM spend on irrelevant queries.

Inline Chunk Citation Enforcement

Every chunk inserted into the prompt context is labeled with its exact chunk_id token inside square brackets. The system instruction directs the generator to cite only retrieved IDs inline and to reject unsupported claims. Post-generation verification flags any cited identifier absent from the retrieved candidate list.
